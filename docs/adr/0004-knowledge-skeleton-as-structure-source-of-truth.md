# ADR-0004: 知识骨架为结构唯一真相源，digest 从「猜树」改为「渲染骨架」

## Status

Accepted（2026-06-16）。是对已上线行为的一次明确改写——现有 `digest` 已经在生产里从碰巧已有的卡片自行推断知识树写进 `_index.md`（见 `PKB-ATOMIC-KNOWLEDGE-PLAN.md` §2.2 / `internal/pkb/digest.go`）。

## Context

PKB 知识库的结构此前由 `digest` **自下而上**生成：每轮从当前 vault 卡片猜一棵知识树写进领域根索引 `_index.md`（`pkb_map`），缺的标 `[缺口]`。这正是原子计划自己诊断的 P3/P7——「digest 凭空猜层级」「领域树会爆炸且很快过期」。

新需求要的是**自上而下、完整、人调方向**的知识体系：先有一棵目标概念树（C#/Java/网安/AI 各一棵），再定向填充其缺口。涌现树与目标树无法各自为政——若两者并存（双真相源），必然漂移（项目已在「工作流漂移」上吃过这个亏，CONTEXT.md 为此立了术语）。

## Decision

**知识骨架成为领域知识结构的唯一真相源；`digest` 不再自行猜测树结构，改为「渲染骨架 + 把卡片归位到节点 + 标缺口 + 把挂不上的卡作为扩展提议」。**

- 骨架以 vault markdown 形式存在（`_index.md` 根 + `topics/` 主题 MOC），由 `digest` **独占增量维护**（复用原子计划护栏 6：先写 `_index.next.md` 校验、快照旧版、原子替换）。
- 骨架由 LLM 自上而下生成（人只播大方向 + 权威源 TOC 校正），人不手改 md，只经 Obsidian 同步查看、通过「调方向前端」掌舵。
- 挂不到任何节点的卡进「待归位区」（`_待归位.md`，领域级 + 全局级），每轮用最新骨架重新匹配再归位；积成簇则触发 LLM 提议给骨架加节点。
- 结构变更按「影响半径」分级：触及卡片数 ≤ 可配阈值的小动作快照后自动应用，> 阈值的大动作（删/合并/重构）推 Matrix 批准。

## Considered Options

- **M2 双真相源**（骨架独立在上层，`_index.md` 仍涌现生成，两者定期对账）——否决：双状态必然漂移，对账成本高，与「工作流漂移」教训冲突。
- **M1 单真相源**（本决策）——采纳。

## Consequences

- **正面**：彻底解决 P3/P7（digest 不再猜结构、领域树不再爆炸）；结构可由人按大方向掌舵；缺口显式化后可被「缺口填充」定向补齐。
- **负面**：`RunDigest` 行为改写，需从「生成树」迁移到「渲染骨架 + 归位 + 提议」；首次为已有领域生成骨架时，存量卡片要做一次全量归位。
- **风险/权衡**：骨架 md 机器独占写（W1），人若绕过约定在 Obsidian 手改会被下轮 digest 覆盖——靠「不手改」约定 + 快照可回溯兜底，不引入人机合并纪律。
