# ADR-0006: Web 前端边界 —— 管机制与观测，不复刻浏览与编辑

## Status

Accepted（2026-06-18）。明确并正式化早期的 DC「不做前端」决策（此前仅散见于 `doc/PKB-KNOWLEDGE-SKELETON-PLAN.md` 的一行注释）。

## Context

PKB 自 ADR-0004/0005 转向「Obsidian vault 为中心 + AI 驱动」后，曾有一条 DC「不做前端」决策，但它用**形态**描述边界（"不做知识库浏览器 / 不做 Web 编辑页 / 只做最小掌舵面"），有两个问题：

- **模糊**：什么算"浏览器"、什么算"掌舵面"没有判据，每遇新功能都要重新争论。
- **会误伤**：按形态看，"在 Web 上直接编辑卡片生成规则"像是越界，但它其实完全应该做——它操作的是生成机制，不是卡片产物。

此次知识库模块大改（总览 / 模块重划 / 问答重构）需要一条能**逐功能判定**的边界，而非形态描述。真正的意图从来不是"不做前端"，而是**不在 Web 里复刻 Obsidian 和文件系统已经做得更好的浏览与编辑**。

## Decision

**Web 前端的边界按「操作的作用对象」划线，而非按界面形态：**

| 作用对象 | 裁决 |
|---|---|
| 生成机制 / 规则 / 方向 / 配置（产物随后由机器据此生成或重生） | ✅ 允许，哪怕"越界"到直接编辑规则 |
| 产物本身（某张卡片正文、某个文件、目录树的增删改） | ❌ 否决，归 Obsidian / 文件系统 |
| 只读地观测产物（统计 / 状态 / 结构投影） | ✅ 允许 |

**一句话：Web 管「机制与观测」，Obsidian/文件系统管「产物与浏览」。**

Web 承载三类、且只此三类：

1. **只读聚合**：散在 vault 里、Obsidian 看不出的全局统计 / 状态 / 健康度 / 结构投影（总览）。
2. **操控生成机制**：批准 LLM 骨架提议、设领域大方向、剪节点，乃至直接编辑"卡片如何被生成"的规则与配置（scope / 阈值 / 生成·填充策略）。
3. **对话问答**。

明确否决：卡片正文浏览/阅读、卡片 CRUD、文件编辑、目录树浏览。

## 例外：资讯库每日存档的时间线浏览

**唯一例外**——允许在 Web 总览内做「资讯时间线」并**只读渲染**资讯库每日存档（`vault/资讯/<领域>/<日期>.md`，type `pkb_feed`）的正文。

| | 知识卡片（vault/archive 原子卡） | 资讯库每日存档 |
|---|---|---|
| 形态 | 原子知识产物 | LLM 综述的**每日报告**（"今天各领域发生了什么"） |
| 用途 | 体系化查阅、长期沉淀 | 按日期**时间线**翻阅、看完即弃 |
| Obsidian 适配 | 强项（双链/搜索/图谱） | 弱项（无现成的"按日期扫各领域"时间线视图） |
| 裁决 | 守判据：归 Obsidian / 原文外链，**不**在 Web 渲染正文 | **例外**：Web 可只读渲染 |

理由：资讯时间线是 Obsidian 给不了、Web 能做顺的**观测视图**，符合本决策"Web 做机器/文件系统给不了的观测"的精神；资讯综述是报告类产物而非知识产物，渲染它 ≈ 看一份生成报告，不构成"知识库浏览器"。

**边界（防类推侵蚀）**：此例外严格限定资讯库每日存档（`pkb_feed`）。**不得**据此在 Web 渲染知识卡片（vault/archive 原子卡）正文——那仍是被否决的浏览器行为。

## Consequences

- **正面**：边界可逐功能判定，不再每次争论；前端聚焦机器/文件系统给不了的独占价值（全局观测、机制操控）；省去复刻 Obsidian 的维护成本；与 ADR-0004 W1（产物机器独占写、人不手改）天然一致。
- **负面**：要读某张卡片正文，得去 Obsidian / 文件系统（Web 至多给"在 Obsidian 中打开"的深链或同步），Web 内不提供完整阅读器。
- **风险/权衡（判据灰区）**：
  - 问答的"卡片引用"必须是**只读指针**（标题 / 路径 / 片段 + 深链），**不得**在 Web 内渲染整张卡片正文——否则问答页会悄悄长成浏览器，越界。
  - "直接改卡片生成规则"这类越界面要守住"改的是规则、不是产物"——规则改完由机器重生卡片，人不在 Web 落笔到产物文件。
  - 知识搜索的结果同理：只列「元信息 + snippet 片段 + `source_url` 原文外链 + 路径」，点击**不在 Web 渲染卡片正文**（archive 卡的"看全文"=回原始网页）。现成的 `GET /api/knowledge/files/read` 全文端点与未挂路由的文件浏览器页（`KnowledgeFiles.tsx`）正是被本决策排除的入口，**不得为搜索/问答接回**。
