# ADR-0005: PKB 分「知识库 / 资讯库」双子系统 + 晋升闸

## Status

Accepted（2026-06-16）。

## Context

PKB 此前是一条管线：RSS/爬取入库 → 打分分流 → 高分原子化 → digest 综述。但两类内容的生命周期根本不同：

- **稳定体系知识**（C# delegate、Java GC、网安原理、AI 算法）——价值衰减慢、应按结构去重沉淀、模型本就懂可生成。
- **时效资讯**（漏洞通告、框架新版、AI 动态）——价值衰减快、同事件多源是信号不该强去重、模型 cutoff 后不知道必须爬。

把两者塞进同一条管线、同一种组织方式（无论纯骨架还是纯时间线）都会互相伤害：资讯会撑爆并污染知识骨架，知识会被时效流的高频噪声淹没。

## Decision

**PKB 拆成两个组织原理不同的子系统，中间一道「晋升闸」连接：**

- **知识库**：按知识骨架树组织（见 ADR-0004）、激进去重、衰减慢；缺口由「缺口填充」自上而下补齐，卡片必须带可核实出处（见下）。回答「这个领域的知识全貌是什么」。
- **资讯库**：按「领域 + 每日」组织（`资讯/<领域>/<YYYY-MM-DD>.md`，一天一文件，与现有 DailyReportService 日报联动）、宽松去重、衰减快、只追加不删；复用现有 RSS 爬取与 brief/日报机制，资讯条目只活在每日存档里、**不存独立原子卡**。回答「今天这个领域发生了什么」。
- **晋升闸**：LLM 从资讯流中识别出的**耐久知识点**（原理/方法/模式，非事件）才晋升进知识库骨架，由 score 的 `durability`+`novelty` 维度把闸；事件性资讯留在资讯库自然失去时效。

配套：知识库卡片带「出处 / 置信度」——模型生成的卡也必须给可核实引用，系统**抓取并核实**该引用是否支撑卡片（crawled/verified=高、unverified=中、llm-only=低），低置信卡进 audit 计数。

## Consequences

- **正面**：资讯不再污染知识骨架；知识库可激进去重、资讯库可宽松留档，各自最优；资讯库≈现有 brief 持久化，新增面小。
- **负面**：晋升闸是一道新的 LLM 判定步骤；资讯库新增「分领域分日落盘」逻辑。
- **风险/权衡**：资讯条目不存独立卡 → 单条资讯不可被独立检索（只能在每日存档里翻）；这是为控制 vault 膨胀的有意取舍，真有强检索需求再评估。
