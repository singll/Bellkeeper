## 现有路由能力与缺口

检查依据为当前仓库源码和生产配置 API；相关接口见 [LLM-GATEWAY-API.md](LLM-GATEWAY-API.md)。

| 位置 | 已有能力 | 与本需求的差距 |
|---|---|---|
| [llm_task_router.go](../internal/llmgateway/llm_task_router.go) | 识别 `coding/classify/summary/qa/long_context/chat/rule_generation`；从任务头、调用方、模型名等推断；编码有复杂度估计 | 没有独立场景 ID 与默认关闭的本地分流开关；短提示词不能代表低风险或低难度 |
| [llm_proxy_request.go](../internal/llmgateway/llm_proxy_request.go) | 请求模型匹配虚拟组，或直接匹配渠道；编码策略调用复杂度判定 | 不会仅因登记本地渠道就把小任务改投本地；当前 `codingPref` 给 `DetectComplexity` 传 `nil` headers，不能把复杂度头当作完整已接入能力 |
| [llm_model_group.go](../internal/llmgateway/llm_model_group.go) | 组策略、编码费用层级、任务类型过滤、粘性会话 | `eligibleMembers` 在任务过滤为空时回退到可用成员；粘性绑定可以先于任务过滤返回，`task_types` 不是严格隔离边界 |
| 代理会话绑定 | 已有会话优先复用健康渠道，保护上下文与缓存 | 场景权限必须在复用之前重新检查，禁止因旧绑定跨越场景或继续使用已关闭的本地策略 |
| 模型组成员能力 | 可配置上下文与输出上限 | 不能以模型厂商标称窗口替代本机 32K 部署上限；直接调用也要有一致的容量预检 |

结论：已有任务感知和编码分层的基础，但缺少“**只有具体场景明确启用，才自动选择本地模型**”的完整能力。不能只把 Gemma 加入 `pool-chat-free`、`pool-summary` 或 `pool-pkb` 就视为实现。

## 必须满足的行为

1. **默认关闭、逐场景启用。** 增加稳定的场景标识及本地策略。未配置、关闭、未知场景继续原有路由；显式开启的场景才允许自动使用本地模型。新场景不继承其他场景的开启状态。
2. **场景来源可信。** 内部调用由服务端业务入口赋值；外部场景声明必须绑定调用方权限，不能通过伪造 header 获得路由权限。队列任务保存场景信息和策略版本，出队时再次检查当前启用状态。
3. **识别部署位置与能力。** 明确区分本地、远程及所需能力；`is_free/tier` 只描述计费或选择偏好，不能代替本地标记。各场景配置允许任务、模型、预算与失败策略。
4. **资格检查先于选择。** 先检查场景开关、任务限制、上下文、输出预算与并发，再进行组选择、粘性复用或重试；任何兜底都不能重新放入被场景策略排除的本地渠道。跨场景会话或配置关闭后必须重新评估绑定。
5. **保留原 API 路由。** 对未通过本地条件的请求，按场景决定继续原模型组或返回明确原因；不能把同名云模型悄悄别名到 Gemma。手动指定本地模型的请求保留显式语义，不因失败默默改用收费 API。
6. **回退单独配置。** 本地故障、超时、超限、截断、JSON/业务校验失败可以触发回退，但必须由该场景允许。`local_only` 禁止把数据发到外部 API。已输出流式内容或触发工具副作用后，不自动重放整个请求。
7. **可取消、有容量上限。** 本机两槽由 Bellkeeper、CPA 和其他直连应用共同使用。Bellkeeper 内的限流不等于全局并发控制；实现时必须明确共享入口或上游背压，避免无限排队。客户端取消应取消上游请求。
8. **可观察、可回滚。** 记录场景、策略版本、选用模型、选择/拒绝原因、冷启动与排队时间、首字/总耗时、token、校验结果、回退原因及 API 用量。常规日志不保存密钥或完整私人材料；单场景开关应可撤回且影响后续请求。

建议第一轮试点输入不超过约 8K token、输出 256–1024 token；这些是待场景评测确认的初始预算，不是本次已生效配置。实际预检需计入系统提示词、历史、工具定义、模板与预留输出，总量低于本机 32768 上限。冷启动、排队和长输入的超时应分别考虑，不承诺小请求测试的延迟适用于长材料。

## 场景边界与验收方法

下表全部为候选方向，**当前没有开启任何一项**。

| 候选场景 | 可交给本地的部分 | 必须验证 / 保留 API 的部分 |
|---|---|---|
| RSS / 网页分类 | 短正文领域、标签、固定枚举 | JSON schema、字段枚举与业务对应关系；正文指令按数据处理 |
| 知识事实抽取 | 来源明确的版本、数字、实体与事件 | 保留来源定位；材料未给出的字段允许 null；重要事实复核 |
| 知识整理 | 分段摘录、短摘要草稿 | 完整知识卡片、复杂关系、自动发布仍使用原流程；不能因本地初筛永久丢弃资料 |
| 简单问答 | 检索后、证据充分的短回答 | 检索由应用完成；缺证据或重要结论转 API / 明示不足 |
| 小范围编码 | 单函数、测试草稿、局部转换 | 执行真实测试；复杂调试、并发、安全与架构任务保留 API |
| 长思考、深度研究 | 分段提取素材 | API 主导研究、综合推理和结论；不将整项研究自动降到本地 |

结构化格式和模型自报 confidence 都不能证明内容正确。接受条件应来自可执行校验和人工标注的真实场景样本；检索资料中的指令不能驱动命令执行或权限修改。启用试点前，需要逐场景约定质量、延迟和回退率门槛，统计实际省下的 API 请求和 token，不用小样本推算全量节省比例。

## 后续实施验收清单

- 未配置 / 关闭 / 未授权场景，短任务和 `is_free` 模型都不能触发本地分流。
- 开启一个场景只影响该场景；全部关闭后原有模型组和业务行为恢复。
- 覆盖非流式、流式、进程内调用、外部 API、持久队列、会话绑定及失败重试路径。
- 原会话来自本地但本次场景关闭、跨场景复用、任务过滤为空时，均不能绕过资格检查。
- 验证输入加输出超限、空闲唤醒、并发排队、取消、429/5xx、超时、空响应、JSON 错误与截断。
- 验证允许回退和 `local_only` 两个方向；流已开始或工具已执行时不重复请求。
- 使用私有真实任务集记录质量与 API 节省；原云模型组回归通过后，再单独批准启用场景。
