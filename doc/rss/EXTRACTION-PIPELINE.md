# 正文提取链路

> 本文档定义 Bellkeeper 在 RSS 文章正文提取中的默认策略。

---

## 推荐组合

- **RSSHub**：feed 聚合与标准化入口
- **Trafilatura**：正文提取主力
- **Firecrawl**：复杂站点兜底

---

## 分工

### RSSHub

负责：

- 提供统一订阅入口
- 输出文章 URL、标题、来源元数据

不负责：

- 正文提取
- 页面渲染
- 最终文件落地

### Trafilatura

负责：

- 普通文章页正文抽取
- Markdown / 文本主路径输出
- 低成本、高吞吐主流程

### Firecrawl

负责：

- JS 重页面
- 主提取失败时的兜底
- 特殊复杂站点

---

## 默认决策顺序

1. RSSHub 提供候选文章 URL
2. Bellkeeper 先做 URL 去重
3. 正文提取先走 Trafilatura
4. 如失败或质量过差，再切 Firecrawl
5. 提取成功后进入文件治理与落地流程

---

## 为什么不是 Firecrawl 全量主跑

因为这条链路的目标是：

- 稳定地把文章落地为文件
- 降低对重型远程抓取能力的依赖
- 控制成本与复杂度
- 把复杂能力留给真正需要它的站点

所以更合理的默认策略是：

**Trafilatura 主跑，Firecrawl 兜底。**
